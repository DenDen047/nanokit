# 吹き出し対話レポート

読者が知らない領域の **仕組み・設計・現在地** を、素人の問いと上級者の答えの往復で説明する単一 HTML レポート。解説文より読まれるのは、**読者が引っかかる場所に、先回りして疑問が書いてある**から。

出力先は `<project>/docs/YYYY-MM-DD_<topic>-dialogue.html`。[`template.html`](template.html) をコピーして書く (CSS は既存レポート 2 本で検証済み。レポート側でいじらない)。

## 二人の役割

| | 素人 🙋 | 上級者 🧑‍🏫 |
|---|---|---|
| 発話 | 1 ターン 1 問、2 文以内 | 結論 → 根拠、最大 3 段落 |
| 仕事 | 読者の代理として引っかかる | 答える。要約もこちらの仕事 |
| 禁止 | 相槌・要約・司会進行 | 長広舌・訊かれていない話 |

**素人の質問が品質を決める。**「〜について教えてください」は司会進行であって疑問ではない。実際に引っかかる形で書く。

- 素朴な代案 — 「通し番号でよくないですか。0001.png、0002.png みたいに」
- 違和感 — 「1 枚落ちても他は続行って、雑じゃないですか」
- 前提への疑い — 「星が付いていない画像を『嫌い』扱いしていいんですか」
- 語の意味 — 「arm ってなんですか。腕？」

上級者は反論に正面から答える。「鋭い。そこがこの設計で一番ややこしいところです」と認めてから説明してよい。**答えられないものは答えない** — 「決まっていません」「ここから先は私の読みであって、設計文書として決まっているものではありません」と地の位置を明示する。

## 書き方

- **専門用語は普通の言葉 → 括弧で正式名称。** 「何度実行しても結果が変わらない性質 (冪等性)」
- **数字・ファイル名・コード・コメントの引用は原文のまま。** 出典は `<code>` かリンクで添える。
- **1 ターン = 1 論点。** 話題が変わるなら素人の問いを挟む。
- **節は問いで区切る。** `<h2>` は「6. 母集団を混ぜてはいけない」のように答えを含む見出しにし、`.lead` に節の要旨を 1 文。
- **節の着地は `.key` で。** 確定 = `.key.done` (緑)、要点 = `.key` (橙)、未決・リスク = `.key.gap` (赤)。`.tag` に短いラベル。
- 表は吹き出しの中に `.tw` で包んで入れてよい。図 (D2 / matplotlib SVG) と数式は section 直下に置き、作り方は `html-report-writing` の `reference/` に従う。
- 敬体で統一。段落内で改行しない (1 段落 = 1 行)。

## 手順

1. **一次資料で事実を固める** — コード、議事録、Notion、実測値。この段階で「確定 / 推測 / 未決」を仕分ける。推測を確定として書かない。
2. **読者が引っかかる順に問いを並べる** = 目次。前の節の答えが次の節の問いを生む順に。
3. `template.html` をコピーし、header と TOC を埋める。
4. **対話を書く。** 素人の問いを先に全部書き、後から答えを埋めると司会進行になりにくい。
5. **用語表と footer の根拠を書く。** 裏が取れていない点は footer の「未確認」に明示。
6. **`visual-verify` を実行する (スキップ不可)** — ライト / ダーク両方でスクリーンショットを撮り、吹き出しの尻尾の位置、表のはみ出し、狭い幅 (520px) での折り返しを自分の目で確認する。

## アンチパターン

- **素人が物分かりよすぎる** — 「なるほど、つまり〜ですね!」と要約させると読者の疑問が消える。要約は上級者の仕事
- **対話が飾り** — 箇条書きを 2 人に割っただけ。問いを消しても文章として成立するなら、対話にする意味がない
- **上級者が訊かれていないことを話す** — 説明したい順ではなく、訊かれた順に答える
- **アバター絵文字を変える** — 🙋 / 🧑‍🏫 で固定 (読者は絵で話者を追う)
- **CSS をレポートごとに直す** — 修正は `template.html` 側に入れる
- **直接編集** — 原本は `~/nanokit/claude/skills/dialogue-report-writing/`。`~/.claude/skills/` 側は symlink
