TL;DR

機能で見れば Agent Reach の大半は既存資産と重複する（追加インストール無しで使える渠道は実測 15 中 4 件）。 それでも入れる価値は「インターネット取得の入口が 1 つに揃うこと」にあるので、 機能の寄せ集めではなく 1 つの pixi env と 1 つのスキルに構造をまとめて導入した。

今の状態: trial/agent-reach ブランチに導入済みで、 agent-reach / twitter / rdt の 3 コマンドが PATH に出ている。 Exa は npm の mcporter ではなくネイティブ MCP として両クライアントに登録済み。 last30days は撤去。Twitter / Reddit の Cookie 投入も完了し、 X のキーワード検索だけが上流の不具合で使えない状態で稼働している。

Agent Reach の実体 ラッパではなくセレクタ

Panniantong/Agent-Reach は MIT ライセンスの Python CLI で、 15 プラットフォームそれぞれについて「今いちばん動く上流ツール」を選び、インストールし、 doctor で疎通を見て、SKILL.md でエージェントに使い方を教える。 データ取得そのものは上流ツール（gh / yt-dlp / twitter-cli / rdt-cli など）が行い、 Agent Reach は間に立たない。つまり 価値の本体はコードではなく「選定と手順の維持」にある。 これは今回の判断の土台でもある。個々の機能は代替できても、 どのプラットフォームをどの裏側で取るかが 1 か所に集まっている状態は代替しにくい。

既存環境との重複

用途ごとに、いま何で足りているか。重複 は機能が増えない、新規 は本当に増える。

用途採用した裏側既存との関係
Web 検索Exa MCP（ネイティブ登録）新規 WebSearch / Codex 検索委譲とは別の英語・技術寄りの検索
Web ページ読み取りJina Reader → scrapling MCP → WebFetch重複 3 段の再試行チェーンとして整理し直しただけ
YouTube 字幕yt-dlp（pixi global）重複 JS runtime 設定という実利のみ
GitHubgh（pixi global）+ deepwiki MCP重複
RSSfeedparser（env 内）小
Twitter / Xtwitter（Cookie）新規 代替手段が無かった
Redditrdt（Cookie）新規 同上
小红书 / B站 / 雪球 / 小宇宙 / V2EX / FB / IG / LinkedIn—不採用 スキルの記述ごと削除（存在しない手段を教えない）
last30days は撤去した。 Reddit / X / YouTube を横断する同種のスキルだったが、 必須の SCRAPECREATORS_API_KEY が環境にも Keychain にも無く機能していなかった。 入口を 1 つにするという今回の趣旨からも、動かない二番目の入口は残さない。

非互換ポイント 7 件

公式手順のまま入れると、この環境の設計原則を 7 か所で踏む。すべて回避または明文化した。

1. install --system が pixi-only を壊す 回避

--system は brew install / apt-get install / npm install -g / pipx install を直接呼ぶ。 そもそも ~/.zshenv で GLOBAL_RCS を落としているため brew は PATH にすら居ない。 → このモードは使わず、必要な CLI を tools/agent-reach/pixi.toml に自前で固定した。

2. skill --install が単一ソースを壊す 回避

このサブコマンドは ~/.claude/skills/ と ~/.agents/skills/ に SKILL を実体コピーし、 既存が symlink なら消してから置く。2026-07 に「実体ディレクトリが 1 つ紛れて配布が静かに壊れた」事故と同じ形。 → スキルは claude/skills/agent-reach/ に vendor し、agent-config-sync の symlink 配布に乗せた。 禁止コマンドは SKILL.md 冒頭と pixi.toml のコメントに明記。

3. スキルの発火条件が広すぎる 修正

同梱 SKILL.md の description は 「MUST USE ... anything on the internet」で、 ultrasurvey / knowledge-base-query / WebSearch / scrapling / deepwiki、 さらに「検索レッグは Codex に投げる」運用と正面衝突する。 → プラットフォーム名か URL が出たときだけに絞り、 「オープンな調査は ultrasurvey へ」と明示的に除外を書いた。

4. 更新チェックの催促 削除

常設ルール 5「タスクごとに check-update して新版を毎回知らせろ」は静かな自動化に反するので削除した。

5. Cookie 認証の BAN リスク 緩和

Twitter / Reddit はどちらも Cookie 前提で、上流も「捨てアカウント推奨、高頻度呼び出しは BAN リスク」と明記している。 → 捨てアカウント運用を前提とし、スキル側に「読み取り専用」「間隔を空ける」 「followers / following の列挙は禁止」を明記した。 書き込み系コマンド（rdt comment など）は呼ばせない。

6. yt-dlp の二重管理 許容

Agent Reach は依存に yt-dlp[default] を持つため env 内にも別実体が入る。PATH 上の pixi global 版が優先されるので実害は無い。 なお PATH 上の yt-dlp は 2026.03.17 と 5 か月前で、本体が更新を促してくる（pixi global update yt-dlp）。 pixi-global.toml に別作業の未コミット変更があるため今回は触っていない。

7. doctor が symlink を辿らない 明文化

Agent Reach は認証情報の保護として「private path は symlink を辿らずに読む」実装になっている (read_small_text_no_follow)。ところが dotter 配布はまさに symlink なので、 ~/.config/yt-dlp/config を doctor が読めず、設定済みなのに警告が残る。 実際には読まれていることを確認済み: 

$ yt-dlp -v --simulate "ytsearch1:test" | grep "User config"
[debug] User config ".../.config/yt-dlp/config": ['--js-runtimes', 'node']

→ 実体ファイルに置き換えれば警告は消えるが、それは単一ソースを捨てるということ。 警告のほうを既知の誤検知として SKILL.md に書いた。将来のセッションが「直そう」としないための予防線。

採否の判断

段内容判断
Tier 0 Exa MCP のネイティブ登録 / yt-dlp の --js-runtimes node 採用・完了
Tier 1 Agent Reach 本体をルータ + スキルとして導入 採用・完了
Tier 2 Twitter / Reddit（twitter-cli / rdt-cli） 採用・配管は完了、Cookie 投入待ち
Tier 3 OpenCLI / 小红书 / B站フル / 雪球 / 小宇宙 / LinkedIn 不採用（npm -g、Chrome 拡張の二重化、使う場面が無い）
構造上の要点: 上流 CLI をツールごとに別プロジェクトへ散らすと、 「インターネット取得の入口が 1 つ」という利点がすぐ崩れる。 そこで 3 コマンドを 1 つの pixi env にまとめ、共有ラッパ run-in-env を 3 つの名前で配る形にした（pixi global の exposed と同じ発想）。 env・lock・更新の単位が 1 つで済む。

配布経路

緑が今回追加したもの、橙が既存の配布機構、赤が 使ってはいけない公式コマンド。新しい機構は増やしていない。

実施したこと

すべて trial/agent-reach ブランチ上。pixi-global.toml の未コミット変更（shellcheck 追加）には触れていない。

1. 3 コマンドを 1 env にまとめた

tools/agent-reach/
├── pixi.toml       # agent-reach (rev 固定) + twitter-cli + rdt-cli
├── pixi.lock       # linux-64 / linux-aarch64 / osx-arm64
├── run-in-env      # 共有ラッパ。$0 の名前をそのまま env 内で実行
├── agent-reach ──┐
├── twitter ──────┼─→ run-in-env への symlink
└── rdt ──────────┘

dotter は 1 つの source を複数の target に配れない（TOML のキー重複になる）ため、 リポジトリ側に 3 つの名前を symlink として置き、それぞれを ~/.pixi/bin/ に配っている。 run-in-env は twitter のときだけ、ユーザーが自分で保存した Cookie を ~/.agent-reach/config.yaml から環境変数に橋渡しする（値は表示しない）。

検証: agent-reach v1.5.0 / twitter 0.8.5 / rdt 0.4.2 が 同一 env で解決し、~/.pixi/bin/ 経由で 3 つとも起動することを確認済み。

2. Exa は npm を経由せずネイティブ MCP に

Exa の実体はキー不要の HTTP MCP なので、nanokit スクリプトの sync_shared_http_mcps に 1 行足して、既存の scrapling / zotero / deepwiki と同じ経路で Claude / Codex の user scope に登録した。 

register_shared_http_mcp exa "https://mcp.exa.ai/mcp" "$diff_only"
要確認: Claude 側は claude mcp list で ✔ Connected。 Codex 側は登録に成功したが、その過程で timed out waiting for OAuth callback が一度出た。 エントリ自体は enabled: true で残っているので、Codex から初めて使うときに実際に応答するか確認したい。

3. yt-dlp 設定を nanokit 管理下に

yt-dlp/config を追加し、dotter で ~/.config/yt-dlp/config に配った（既存の uv.toml と同じ形）。

4. スキルを vendor して絞った

claude/skills/agent-reach/ に rev 93ae1d1 の英語版をコピーし、 description を絞り、更新催促を削り、未採用プラットフォームの記述を references ごと削除した。 残したのは search / web / video / dev / social（Twitter・Reddit のみ）の 5 本。 doctor の既知の誤検知 3 件（YouTube・GitHub・Exa）も明記した。

5. last30days を撤去

~/.claude/skills/last30days の symlink と claude/external/ を削除し、ARCHITECTURE.md の記述も落とした。

認証の状態 2026-08-13 実測

Cookie 投入後に 1 コマンドずつ実際に叩いて確認した結果。

コマンド結果備考
rdt popular / sub / read / search✅ 動作認証情報は ~/.config/rdt-cli/credential.json（600）
twitter feed✅ 動作捨てアカのホームタイムラインが返る
twitter user / user-posts / tweet✅ 動作特定アカウントを追う用途はこれで足りる
twitter search❌ HTTP 404Cookie が正しくても失敗する。下記の上流不具合
X のキーワード検索は使えない: twitter-cli は x.com の JS を スクレイプして transaction ID を組み立てるが、そのスクレイパが現在の X に対して壊れている （実行のたびに Failed to init ClientTransaction が出る）。検索エンドポイントが道連れになっている。 PyPI の最新は 0.8.5（2026-03-17）で、これが既に入っている版なので更新では直らず、 上流が案内する代替バックエンド（OpenCLI）は不採用のため無い。 → user-posts で個別アカウントを追うか、素直に「X の全文検索は不可」と答える運用にした（スキルに明記）。
残っているのは判断だけ: Claude Code を再起動すると Exa MCP がツールとして見えるようになる。 Codex 側の Exa は登録時に OAuth コールバックのタイムアウトが出たままなので、初回利用時に応答するか見ておきたい。 あとは 1〜2 週間使って、残すなら trial/agent-reach を main へ merge。

撤去手順

git switch main                       # trial ブランチを捨てる
./nanokit deploy                      # 3 コマンドと yt-dlp config を落とす
rm -rf ~/.agent-reach                 # Cookie を含む設定（作られていれば）
claude mcp remove exa -s user && codex mcp remove exa

公式の agent-reach uninstall は npm / pipx で入れた上流ツールの削除案内も出すが、 本構成ではそれらを入れていないので使う必要はない。
